# Stage 13: Candidate Coverage Matrix

**Date:** 13 September 2026. **State:** generated design candidates, not implemented or executed examples.

This original synthetic pool contains **50 candidates: ten per level**. Each has a small reproducible repository representation and all fifteen required matrix dimensions. The [selection and fixture designs](2026-09-13-stage-13-progressive-examples.md) explain the combined-coverage decision. No external repository, historical incident or published benchmark is being represented as the source of these invented fixtures.

Legend: CT/CO/F/C identifiers are the accepted Stage 4–5 change, contract, failure and capability models. CMD numbers are the twelve Stage 11 prompt-level commands, not executable subcommands. “engineering” means `software-engineering`, with its own complete self-review; the optional evaluator means independently installed `software-evaluate`. All implementation candidates also require ordinary evidence/final scope handling even where the abbreviated command list emphasises targeted modes. Quality names are distinct dimensions, not a score. “None” in the pack column is an intentional core-only/non-activation case, not missing security or compatibility responsibilities.

The two tables per level join on candidate ID. Together they contain exactly **50 × 15 = 750 nonempty required dimension cells**. Identity, capability tags and disposition are additional fields. Design representations identify files/modules, seedable state, real boundaries and oracles; source fixture creation remains Stage 17–19 work.
