## Reconciliation and qualified production hypotheses

**Business identity versus delivery identity:** EP08 establishes meaning; EP11 supplies the transaction boundary; EP12 exposes unknown remote results. A delivery tag, transport ID, payload hash and caller operation ID are not interchangeable by name. The implementation must use the actual supported identity and detect conflicting intent where the contract requires it. A hash is not proof that two distinct user intents are the same operation.

**Safety versus progress:** EP10/EP14 do not promise completion under permanent failure. EP06/EP09 require realistic capacity and owner-defined handling of invalid work. Retrying forever may preserve one message but prevent useful progress; dropping it may violate a different invariant. The pack should expose and implement the actual recovery/dead-letter policy, not choose business loss silently.

**Local transactions versus external effects:** EP11 supports atomic local state where feasible. EP12 is an explicit counterexample to applying that recipe across a carrier boundary. An outbox can preserve intended delivery but does not by itself make an arbitrary external side effect exactly once. The expected solution uses supported identity, idempotent semantics, reconciliation or approved compensation with actual evidence.

**Ordering versus concurrency:** EP13 does not demand global order; it identifies the required scope. Commutative independent operations can run concurrently. A per-entity state transition may need a version/sequence guard. Broker FIFO and replay characteristics remain P4 facts to verify, not conclusions imported from generic architectural language.

**Tests versus claims:** EP01/03/04 make a useful fault-injection seam precise; EP02 keeps resulting evidence fresh. A deterministic delivery model is valuable for reproducing a commit/ack crash window and must remain labelled as a model. It does not validate a broker's failover, throughput or real transport/driver semantics.

General intent, preservation, truthful evidence, bounded repair and authority remain core responsibilities. The pack deepens continuing event-effect analysis and fault criteria. Project-specific identities, payloads, acknowledgement policy, ordering, retention, capacity and live replay permission remain explicit external inputs. No finding creates a generic event runtime or copies a book's application examples.
